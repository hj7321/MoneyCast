# MoneyCast 뉴스 API 계약

기본 주소는 `http://127.0.0.1:8787`입니다. 웹 개발 서버가 `/api`를 프록시합니다. 네이티브 앱에서는 접근 가능한 API 주소를 별도로 지정합니다.

`npm run build` 후 `npm start`를 실행하면 같은 서버가 `apps/web/dist`의 웹 빌드와 `/api`를 함께 제공합니다. 브라우저에서 `http://127.0.0.1:8787`을 엽니다. 웹 파일과 SPA 경로는 GET/HEAD를 지원하고, 없는 `/api/*`는 HTML 대신 JSON 404를 반환합니다. 빌드 폴더 밖 경로·심볼릭 링크와 숨김 파일은 제공하지 않습니다. HTML은 재검증하고 해시가 포함된 정적 자원은 장기 캐시합니다.

| 요청 | 응답 |
| --- | --- |
| `GET /api/health` | 서비스 실행 상태 |
| `GET /api/companies?q=삼성` | `{ "companies": [...] }`. 고정 식별 목록 검색이며 실시간 상장 목록이 아닙니다. |
| `GET /api/news?companyId=krx%3A005930` | 공용 `NewsAnalysis` 계약 |
| `GET /api/cron/collect` | 예약 수집. `Authorization: Bearer <CRON_SECRET>`가 필요하며 `{ "refreshed": [...], "failed": [...], "skipped": [...] }`만 반환 |

회사를 선택하지 않았거나 ID가 일치하지 않으면 400, 지원하지 않는 메서드는 405입니다. 뉴스 상태는 HTTP 200 응답의 `status`로 구분합니다: `not_configured`, `insufficient`, `ready`, `error`, `rate_limited`. 데이터가 없으면 `articles`는 빈 배열입니다. 제공자 오류 응답 원문과 비밀키는 클라이언트로 전달하지 않습니다. 예약 수집 경로는 `CRON_SECRET`이 없으면 503, 인증값이 없거나 다르면 401이며(상수 시간 비교), 응답은 캐시하지 않습니다.

## 출처 결합

`NEWS_PROVIDER`가 `marketaux`(기본)이면 `NEWS_SOURCES`의 출처를 함께 조회합니다. 기본값은 `marketaux,gdelt`이며, 알 수 없는 출처 이름은 설정 오류입니다. 게이트웨이(`NEWS_PROVIDER=gateway`)는 단독으로만 사용합니다.

- 출처마다 제한 시간·쿨다운·오류를 따로 처리하고(`Promise.allSettled`), 응답의 `sources`에 출처별 `ok`·`empty`·`skipped`(예약 수집 때만 조회)·`not_configured`·`rate_limited`·`error`와 기사 수, 재시도 시각을 남깁니다. 기사마다 수집 출처(`sourceProvider`)를 표시합니다.
- 같은 기사는 하나로 합칩니다. URL은 호스트 소문자화·`www.`/`m.`/`amp.` 제거·추적 파라미터 제거·쿼리 정렬로, 제목은 `[속보]` 같은 태그와 " - 매체" 꼬리를 지운 뒤 비교합니다. 같은 제목이거나 48시간 안에 2-gram 유사도 0.8 이상이면 같은 기사로 보고, 분류된 기사를 대표로 남겨 나머지는 `alsoReportedBy`(최대 10곳)에 둡니다.
- 일부 출처만 실패하면 성공한 출처로 결과를 만들고 30분만 캐시합니다. 건너뛴 출처(`skipped`)는 실패로 보지 않으므로 정상 결과의 6시간 캐시를 유지하고, 성공으로도 세지 않습니다. 모두 실패하면 7일 이내의 마지막 정상 결과를 `servedFrom: "stale"`과 `refreshAttemptedAt`으로 표시해 반환하며, 이 응답은 CDN에 캐시하지 않습니다. 정상 결과가 없으면 기존 오류 상태를 반환합니다.

## GDELT DOC 2.0

[GDELT DOC 2.0 API](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/)는 키가 필요 없습니다. **예약 수집에서만** 고정 주소 `https://api.gdeltproject.org/api/v2/doc/doc`에 `mode=artlist`, `format=json`, `maxrecords=75`(GDELT 기본값), 최근 7일, 최신순으로 요청합니다. 요청 시 갱신에서는 요청하지 않고 출처 상태를 `skipped`로 둡니다. 검색식은 회사 이름을 세 번 이상 쓴 기사만 찾는 `repeat3:"<단어>"`에 회사별 영어 검색식을 더합니다(예: `repeat3:"Samsung" "Samsung Electronics"`). `repeat`는 한 단어만 받고, 제목만 검색하는 연산자는 없습니다. GDELT는 영어 기계 번역 색인을 검색하므로 다른 언어 기사도 찾을 수 있습니다.

- 제목·URL·도메인·언어·처음 확인한 시각(`seendate`)만 제공되고 설명과 감성 점수는 없습니다. 시각은 `timeKind: "seen"`으로 표시하며 게시 시각과 다를 수 있습니다.
- 제목에 회사명이 있고 제외어(다른 계열사·우선주·동명이인 등)가 없을 때만 포함하며 `identity: "name_match"`로 표시합니다. HTTPS 원문 링크만 사용하고 최대 15건입니다.
- 프로세스당 5초에 1회만 요청하고, 대기가 5초를 넘으면 그 요청은 호출 제한으로 처리합니다. 429나 "limit requests" 응답은 60초 쉽니다.
- 응답에 10~16초가 걸리는 경우가 많아, 예약 수집이 남긴 시간만큼(3~30초, 보통 30초) 기다리며 기한이 없으면 8초입니다. 실패는 서버 로그에 `GDELT request failed: timeout after 10s`, `HTTP 500`, `network error`처럼 종류만 남깁니다.
- 2026-10-28 확인: 영어 번역 본문까지 검색하므로 이전 검색식 `"Samsung Electronics"`는 결과 50건 중 제목에 회사명이 있는 기사가 1건뿐이었습니다(한국어 44건). `repeat3:` 검색식은 엔비디아에서 50건 중 11건이었습니다. 사용자 PC(가정용 IP)에서도 5번 중 4번 429가 왔고 공용 IP에서는 첫 요청부터 오기도 해, 화면 요청에서는 부르지 않습니다. 같은 날 다시 점검했을 때도 실제 요청 3번이 모두 실패했습니다(429 두 번, 네트워크 오류 한 번). 429 뒤 60초를 쉬는 동안에는 다음 회사도 요청하지 않으므로, 예약 수집 한 번에 429가 한 번 나면 그날 나머지 회사의 GDELT 기사는 없습니다. `npm run ai:check`는 예약 수집과 같은 경로로 GDELT를 부릅니다.
- [이용 조건](https://www.gdeltproject.org/about.html)에 따라 화면에 GDELT Project 출처와 링크를 표시합니다.

## Marketaux 실제 뉴스 연결

[Marketaux 공식 문서](https://www.marketaux.com/documentation)에 따른 서버 어댑터가 포함되어 있습니다. [무료 계정](https://www.marketaux.com/register)을 만든 뒤 대시보드의 토큰을 루트 `.env`에 입력합니다. 키는 Git·브라우저·앱·공개 환경변수에 저장하지 않습니다.

```dotenv
NEWS_PROVIDER=marketaux
MARKETAUX_API_TOKEN=your-server-only-token
```

`npm run dev`는 `.env` 변경을 감지해 API를 다시 시작합니다. `npm start`는 설정 변경 후 직접 다시 시작해야 합니다. 개발 서버를 중복 실행하지 마세요. 키가 없으면 외부 API를 호출하지 않고 `not_configured`를 반환합니다.

- 고정 HTTPS 주소 `https://api.marketaux.com/v1/news/all`에 서버에서만 요청합니다. 제공자 인증 규격상 토큰은 상류 요청의 `api_token` 쿼리에만 포함되며, 요청 URL·오류 본문을 로그나 클라이언트로 전달하지 않습니다. 리디렉션은 허용하지 않습니다.
- 최근 7일, 회사별 최대 3건, 유사 기사 그룹화, 기업 엔터티 필터, 영어·한국어(`language=en,ko`)를 적용하고 원문 언어를 표시합니다. 3건은 최신순이 아니라 선택한 기업과의 일치 강도순(`sort=entity_match_score`, 내림차순)으로 고릅니다. 최신순으로 받았을 때 2026-10-28 점검에서 점수 기사 20건 중 12건이 회사를 지나가듯 언급한 업종 시황·다른 회사 기사였기 때문입니다. 받은 기사는 화면에서 다시 최신순으로 정렬합니다. 기사 전체 본문·이미지·하이라이트를 복제하지 않습니다.
- 미국 종목은 티커·회사명·국가·주식 유형·제공된 거래소를 대조합니다. 한국 종목은 `/v1/entity/search`에서 종목 코드·회사명·국가·거래소를 검증해 제공자 티커를 찾습니다. 티커 접미사를 임의로 붙이지 않습니다. 식별 결과는 6시간 메모리 캐시하며, 후보가 없거나 모호하면 `identity_unverified` 사유의 안전한 오류를 반환합니다. 기업명이 같아도 다른 시장·주식 유형·우선주는 선택한 보통주를 대신하지 않습니다.
- 매체가 제공한 `description`은 태그를 지운 일반 텍스트로 최대 300자만 저장합니다. `snippet`·`highlights`·본문은 저장하거나 표시하지 않습니다.
- 기사마다 선택한 회사와 일치한 엔터티의 `sentiment_score`만 사용합니다. -1~1 범위에서 양수/음수/0을 긍정/부정/중립으로 표시하고, 점수가 없으면 `unclassified`/미분류입니다. 미분류는 판단 집계에 포함하지 않습니다. 감성 점수는 뉴스 문맥 분류이며 상승 확률이 아닙니다. 점수·분류 주체·제공자 기업 식별 정보·언어를 추적합니다.
- 제공자가 거래소를 생략한 경우 티커·회사명·국가로 대조하되 해당 한계를 표시합니다. 기업 식별 불일치 및 기간 밖 기사는 제외 사실을 표시합니다. 잘못된 필수 필드·점수·JSON·위험한 원문 링크는 오류로 처리합니다.
- 기업 조회와 뉴스 요청을 합쳐 15초 제한입니다. 첫 한국 기업 조회의 두 요청과 제공자 응답 지연을 고려하며 웹·앱 요청은 20초까지 기다립니다. 요청 시 갱신은 AI 판단까지 18초 안에 끝내며, Vercel 함수 최대 실행 시간 300초는 예약 수집을 위한 값입니다. 응답은 JSON 최대 1MiB, 뉴스 최대 3건입니다. 같은 회사의 진행 중 요청을 공유하고 정상 결과는 6시간, 일반 오류·미설정은 5초 캐시합니다. 프로세스 재시작 시 캐시는 사라집니다.
- HTTP 401은 키 확인, 403은 계정 접근 권한·플랜 확인, 402/429는 `rate_limited`로 표시합니다. `Retry-After`를 해석하고 최대 24시간 범위의 재시도 시각을 반환합니다. 헤더가 없으면 402는 15분, 429는 1분을 기본 대기 시간으로 사용하며 서버 결과 캐시가 더 길면 그 시간까지 기다립니다. 제한 기간에는 다른 회사를 선택해도 외부 호출을 보내지 않습니다.

[공식 무료 요금](https://www.marketaux.com/pricing)은 2026-10-27 확인 기준 하루 100회·뉴스 요청당 3건입니다. 기업 식별 요청도 쿼터를 사용할 수 있습니다. 실제 남은 한도와 이용 권한은 계정 대시보드가 기준이며, 한국 종목·한국어 기사 수를 보장하지 않습니다. 자동 추가 페이지는 없으며, 주기적 요청은 하루 한 번의 예약 수집뿐입니다. 현 구현은 로컬 기능 테스트용이며 공개 재배포 시에는 선택 플랜의 이용 조건과 원문 매체의 권리를 확인해야 합니다.

## 선택적 사용자 소유 게이트웨이

기존 HTTPS 게이트웨이 어댑터도 유지합니다. 루트 `.env`에 다음 서버 전용 설정을 지정합니다. `NEWS_PROVIDER`가 없을 때는 기존 `NEWS_PROVIDER_URL`이 있으면 게이트웨이, 없으면 출처 결합(Marketaux·GDELT)을 선택합니다. 게이트웨이를 선택하면 게이트웨이만 사용하며, 실패해도 다른 출처로 바꾸지 않습니다.

```dotenv
NEWS_PROVIDER=gateway
NEWS_PROVIDER_URL=https://your-trusted-gateway.example/news
NEWS_API_KEY=your-server-only-key
```

게이트웨이는 HTTPS만 지원하며 리디렉션은 허용하지 않습니다. 요청은 `POST`, `Authorization: Bearer <NEWS_API_KEY>`, `Content-Type: application/json`입니다. 요청 본문:

```json
{
  "company": {
    "id": "krx:005930",
    "name": "삼성전자",
    "symbol": "005930",
    "exchange": "KOSPI",
    "region": "KR"
  },
  "since": "2026-10-20T00:00:00.000Z",
  "until": "2026-10-27T00:00:00.000Z"
}
```

다음은 **응답 형식 설명용 예시**이며 실제 기사가 아닙니다.

```json
{
  "companyId": "krx:005930",
  "provider": "게이트웨이 제공자 표시명",
  "articles": [
    {
      "id": "unique-source-article-id",
      "title": "형식 설명용 기사 제목",
      "source": "출처 표시명",
      "publishedAt": "2026-10-26T09:00:00+09:00",
      "url": "https://publisher.example/article",
      "sentiment": "neutral",
      "rationale": "제공자가 작성한 분류 근거"
    }
  ]
}
```

분류는 `positive`, `negative`, `neutral`, `unclassified` 중 하나여야 합니다. 점수가 없거나 분류하지 않은 기사는 `unclassified`로 보내며 중립으로 바꾸지 않습니다. 식별자 불일치, 잘못된 필수 필드, HTTPS 이외 원문 링크, 10분을 초과하는 미래 시각, 40건 초과 기사, 1MiB 초과 응답은 오류입니다. 날짜에는 시간대가 필요합니다. ID 또는 원문 URL이 중복된 기사는 한 건만 사용합니다. 기사 내용의 실제 관련성·권리·분류 품질은 게이트웨이 운영자가 검증해야 합니다.

기사의 선택 메타데이터는 `language`, `sentimentScore`, `classificationMethod`, `providerEntity`입니다. `sentimentScore`는 유한한 -1~1 값이어야 하며 점수의 부호와 `sentiment`가 일치해야 합니다. `classificationMethod`는 `provider` 또는 `unavailable`입니다(`llm`은 서버가 두 AI의 합의로 붙이는 값이라 게이트웨이가 보내지 않습니다). `unavailable`이면 `unclassified`이고 점수가 없어야 합니다. `providerEntity`는 문자열 `symbol`, `name`, `country`와 문자열 또는 null인 `exchange`를 담습니다. 이 선택 필드가 없는 기존 게이트웨이 기사도 지원합니다.

게이트웨이 요청 제한 시간은 8초입니다. HTTP 429는 `rate_limited`, 기타 실패와 형식 오류는 `error`로 표시합니다. 같은 회사의 진행 중 요청은 공유합니다. 정상·빈 결과의 메모리 캐시는 게이트웨이 60초, Marketaux 6시간이며 일반 오류·미설정은 5초입니다. 호출 제한은 정상 결과의 6시간 캐시와 구분해 최소 1분 또는 제공자의 재시도 시각까지 기다립니다. 결과 캐시는 최대 100개 회사이며 프로세스를 재시작하면 사라집니다.

## 분석 응답의 추적 정보

`NewsAnalysis`는 기사 목록과 상태 외에 다음 정보를 반환합니다. 시각 문자열에는 시간대가 포함되며 웹·앱은 한국 시간으로 표시합니다.

| 필드 | 의미 |
| --- | --- |
| `asOf` | 분석 요청의 데이터 기준 시각 |
| `newsWindow.start/end` | 근거 집계에 사용하는 최근 7일의 시작·종료 시각 |
| `period.start/end` | 서울 날짜 기준 다음 주 월~금의 참고 기간 |
| `cachedUntil` | 서버가 현재 결과를 재사용하는 만료 시각 |
| `retryAt` | 호출 제한 시 수동 재요청을 허용하는 시각 |
| `provider`, `analysisVersion` | 결과에 기사를 낸 출처와 집계 규칙 버전(`news-evidence-v3`) |
| `factorSummary` | 긍정·부정 박스의 종합 문장(박스당 최대 3줄, 문장마다 근거 기사 ID), 상태(`none`·`single`·`repeated`·`mixed`), 주의 칩 |
| `sources` | 출처별 상태(`skipped`는 예약 수집 때만 조회하는 출처)·기사 수·재시도 시각 |
| `servedFrom`, `refreshAttemptedAt` | `stale`이면 새로 고침이 실패해 이전 결과를 보여주는 중이며, 실패한 시도 시각을 함께 둠 |
| `ai` | 모델별 상태(`ok`·`idle`·`not_configured`·`rate_limited`·`error`·`timeout`)와 판단 건수, 두 모델이 모두 관련 없다고 본 기사 수(`unrelatedCount`), 프롬프트 버전 |

기사에는 선택 필드로 `description`(매체 설명), `rationaleLines`(분류 근거 1~5줄), `topics`(고정 주제 키), `sourceProvider`, `timeKind`(`published`·`seen`), `identity`(`entity_verified`·`name_match`), `alsoReportedBy`, `summary`(AI 요약과 그 기준 `title_description`·`title_only`), `aiJudgements`(모델별 판단), `aiConsensus`(`confirmed`·`provisional`·`withheld`·`pending`), `aiRelevance`(`unrelated`: 두 모델 모두 관련 없음)가 붙습니다. 공용 검증기는 `llm` 분류가 `confirmed`일 때만 방향을 갖도록 하고, `aiRelevance`는 두 모델의 판단이 모두 '관련 없음'일 때만 허용하며, 종합 문장이 관련성 낮은 기사를 뺀 실제 기사 ID만 가리키는지 확인합니다. 이 필드가 없는 v2 응답도 그대로 유효합니다.

`newsWindow`, `cachedUntil`, `retryAt`은 공용 계약에서 선택 필드이며, 현재 서버는 수집 기간과 캐시 만료를 모든 분석 상태에 포함하고 호출 제한 상태에만 재시도 시각을 추가합니다. 오류 응답에서도 비밀값이나 제공자 오류 원문은 반환하지 않습니다.

## 예약 수집과 스냅샷

`vercel.json`의 Cron이 매일 `0 21 * * *`(UTC, 06:00~06:59 KST)에 `/api/cron/collect`를 호출합니다. 8개 회사를 차례로 새로 고치며(출처 요청 간격 때문에 병렬로 하지 않음), 시작 후 200초가 지나면 남은 회사는 `skipped`로 돌려 요청 시 갱신에 맡깁니다. Cron은 재시도하지 않고 중복 실행될 수 있으므로 회사 스냅샷을 덮어쓰기만 합니다.

- 저장소는 **비공개** Vercel Blob입니다(`access: "private"`, 덮어쓰기, 무작위 접미사 없음). Vercel에서는 스토어를 프로젝트에 연결하면 OIDC(`BLOB_STORE_ID`)로, 로컬에서는 `BLOB_READ_WRITE_TOKEN`으로 인증합니다. 둘 다 없으면 스냅샷 없이 동작합니다.
- 경로는 `news/news-evidence-v3/<회사 ID>.json`이고, 최근 분석·갱신 시각·7일 기사 목록(최대 30건, 관련성 낮은 기사와 AI 판단·요약 포함)을 담습니다. 읽을 때 형식·버전·회사·크기(1MiB)를 검증하고 맞지 않으면 버립니다.
- 요청은 메모리 → 스냅샷 → 실시간 순으로 읽습니다. 스냅샷이 아직 유효하면 출처와 모델을 호출하지 않습니다. 만료된 스냅샷의 기사 목록은 새 기사와 합쳐 주간 근거를 이어 갑니다.
- 내용이 같으면 6시간에 한 번만 다시 씁니다(Hobby 고급 작업 월 2천 회). 읽기·쓰기 실패는 경고만 남기고 응답에는 영향을 주지 않습니다.

## AI 교차 판단

Gemini 키나 Cloudflare 키가 있으면 모든 기사를 두 모델이 따로 판단합니다. 감성 점수가 없는 기사는 판단으로 방향을 정하고, 점수가 있는 기사는 두 모델이 점수와 어긋날 때만 바뀝니다. 키가 하나도 없으면 이 단계를 건너뜁니다. 원하는 모델의 키가 빠져 있으면 그 모델은 `not_configured`로 표시되고, 다른 모델의 판단은 `provisional`로 남습니다.

| 모델 | 요청 | 맡는 일 |
| --- | --- | --- |
| Gemini(`GEMINI_MODEL`, 기본 `gemini-3.5-flash-lite`) | `POST https://generativelanguage.googleapis.com/v1beta/models/<모델>:generateContent`, 키는 `x-goog-api-key` 헤더, `responseMimeType: application/json`과 응답 스키마 | 방향·근거 구절·이유·주제·한국어 요약 |
| Cloudflare Workers AI(`CLOUDFLARE_AI_MODEL`, 기본 `@cf/qwen/qwen3-30b-a3b-fp8`) | `POST https://api.cloudflare.com/client/v4/accounts/<계정>/ai/run/<모델>`, `Authorization: Bearer <토큰>`, `temperature: 0` | 방향·근거 구절·이유(요약 없음) |

- 두 요청은 같은 입력으로 **동시에** 보내며, 어느 쪽도 다른 모델의 답을 받지 않습니다. 최종 결과는 코드의 합의 규칙이 정합니다: 같은 방향이면 `confirmed`(`classificationMethod: "llm"`), 방향이 다르거나 한쪽이라도 `uncertain`이거나 관련성 판단이 다르면 `withheld`, 한 모델만 답하면 `provisional`, 둘 다 답하지 않으면 `pending`, 둘 다 관련 없다고 하면 `aiRelevance: "unrelated"`입니다. `confirmed`만 방향을 가지며 나머지는 `unclassified`로 집계에서 빠집니다.
- 점수 기사(`checkScore`): 둘 다 관련 없다고 하면 `aiRelevance: "unrelated"`를 붙이고 점수는 참고로 남깁니다. 둘 다 점수와 정반대 방향으로 일치하면 AI 합의(`llm`·`confirmed`)로, 한쪽만 정반대이고 다른 쪽도 점수 방향이 아니면(중립·판단 불가·관련 없음) `withheld`로 바꿉니다. 이때 `sentimentScore`는 지우고, 분류 근거 첫 줄(`AI 방향 확인:`)에 원래 점수와 두 모델의 판단을 남깁니다. 이 줄은 이후 갱신에서도 유지됩니다. 그 밖에는 점수를 그대로 집계합니다. 2026-10-28 점검에서 두 모델이 함께 점수와 반대로 읽은 3건을 사람이 제목으로 판단했을 때 3건 모두 두 모델과 같았습니다. `unrelated` 기사는 숨기지 않고 목록 아래에 접어 두며, 근거 수준·건수·요약 문장·종합 문장에서 모두 뺍니다. 최근 기사가 모두 `unrelated`이면 요약 문장이 그렇다고 밝히고 판단을 유보합니다.
- 입력은 회사명·별칭·종목 코드·거래소와 기사별 요청 내 임시 ID·제목·매체 설명·매체·언어입니다. 기사 텍스트 속 지시는 따르지 않도록 지시하고 도구는 주지 않습니다.
- 검증: 응답 JSON 형식, 요청한 ID와 한 번씩만 답했는지, 근거 구절이 제목·설명에 실제로 있는지(긍정·부정은 근거 필수), 이유·요약에 입력에 없는 숫자가 있는지(영어로 쓴 숫자 third→3, 같은 금액의 만·억·조 표기 250,000→25만은 입력의 숫자로 봄), 투자 권유·확률·주가 전망 표현이 있는지(기사가 보도한 증권사 의견과 펀드·내부자의 매수·매도는 허용, '매수 기회'·'매도하세요' 같은 권유는 항상 차단), 길이(근거 80자·이유 120자·요약 160자). 근거 구절이 원문에 그대로 있으면 80자를 넘어도 버리지 않고 앞 80자만 남깁니다(`evidence_trimmed`). 근거나 이유가 검증에 실패하면 그 기사의 해당 모델 답을 버리고, 요약만 실패하면 요약만 버립니다.
- 호출 1회당 기사 최대 15건입니다. 이미 판단한 모델에는 같은 기사를 다시 보내지 않고, `provisional` 기사는 빠진 모델에만 보냅니다. 점수 기사도 두 모델이 한 번씩 판단하면 다시 보내지 않습니다. 요약이 없는 기사는 Gemini에 요약만 요청할 수 있습니다.
- 시간 예산: 요청 시 갱신은 전체 18초(출처 10초), 예약 수집은 회사당 60초(출처 35초)이며 모델 호출 1회는 최대 25초입니다. 점수 기사도 방향을 바꿀 수 있으므로 같은 검증(긍정·부정은 근거 구절 필수)을 거칩니다. 요약만 요청한 답은 판단으로 쓰지 않으므로 근거·이유를 검사하지 않습니다. 남은 시간이 6초 미만이면 호출하지 않고 `timeout`으로 둡니다. 마감 뒤에 도착한 답은 버립니다.
- 한도: Gemini 429는 `RetryInfo`의 대기 시간(1분~1시간, 없으면 15분), Cloudflare 429는 하루 무료량 소진(코드 3036)이면 다음 00:00 UTC까지, 그 밖에는 1분 쉽니다. 쉬는 동안에는 외부 호출을 보내지 않습니다.
- 모델 실패·한도·시간 초과·예상하지 못한 오류는 뉴스 응답을 막지 않으며, 기사는 출처의 분류 그대로 남습니다. 키는 헤더로만 보내고, 키가 응답에 되돌아오면 그 응답을 버립니다.

## 로컬 연결 확인 명령

서버를 실행한 상태에서 프로젝트 루트에서 `npm run news:check`를 실행하면 삼성전자의 뉴스 연결을 확인합니다. `npm run news:check -- nasdaq:AAPL`처럼 목록에 있는 회사 ID를 지정할 수도 있습니다. 루트 `.env`의 `PORT`를 사용하며 기본값은 8787입니다. 서버를 새로 시작하거나 외부 제공자에 직접 요청하지 않고 로컬 API를 통해 확인하므로, 서버 캐시가 없다면 제공자 호출 쿼터가 사용될 수 있습니다.

출력은 회사 식별 정보, 상태, 제공자, 기사 수, 기준 시각, 대상 기간과 진단 문구입니다. `--ai`를 붙이면 AI가 판단한 기사(관련성 낮은 기사와 관련성만 확인한 점수 기사 포함)마다 번호·결과(합의·잠정·유보·대기·관련 없음·점수 유지)·두 모델의 판단·근거 구절·제목(제어 문자 제거, 70자)을 한 줄씩 보여 주고, 두 모델이 모두 답한 기사 중 같은 판단의 비율을 계산합니다. 모델 실패는 서버 로그에 `Gemini request failed: HTTP 400 INVALID_ARGUMENT`, `Cloudflare request failed: HTTP 429 (code 3036)`, `Cloudflare answers discarded or trimmed: evidence_not_in_text 2 (of 15)`처럼 상태·코드·사유별 건수만 남깁니다. 키와 제공자 오류 원문은 출력하지 않습니다. 요청별 제한 시간은 20초입니다. 미설정·호출 제한·오류·잘못된 응답·연결 실패는 종료 코드 1이며, `ready`와 `insufficient`는 정상 응답 수신으로 종료 코드 0입니다. `insufficient`나 기사 0건은 뉴스 근거 또는 전망을 확보했다는 뜻이 아닙니다.

## 근거 수준의 의미와 한계

- 최근 7일 구간 안에 게시된 분류 확인 기사 3건 미만, 전부 오래된 기사, 전부 중립, 긍정·부정 상충은 `insufficient`입니다. 분류 확인 기사는 제공자 점수가 있는 기사와 두 AI가 합의한 기사이며, 두 AI가 모두 관련 없다고 본 기사는 점수가 있어도 빠집니다. 두 AI가 점수와 정반대로 합의한 기사는 AI 방향으로 세고, 점수와 AI 판단이 엇갈린 기사는 판단 유보로 뺍니다. 미분류·잠정·판단 유보·관련성 낮은 기사는 목록에 표시하되 충족 수와 요인 집계에서 제외합니다. 미래 시각의 기사도 근거 집계에 포함하지 않습니다.
- 분류를 확인한 최근 기사 3건 이상이고, 긍정 또는 부정 요인이 있으며, 양쪽 분류가 상충하지 않을 때만 `ready`/`moderate`입니다. 이는 기사 집합의 수량·최신성에 따른 표시 규칙이며 예측 정확도나 사실 신뢰도 점수가 아닙니다.
- 다음 주 기간은 서울 날짜 기준 다음 월요일~금요일입니다. 거래소 휴장일과 시장별 시차를 정확히 반영하려면 시장 달력 연동이 필요합니다.
- `asOf`, 기사 원문 URL·게시 시각·ID, 회사 ID, 제공자, `analysisVersion`을 응답에 남겨 향후 저장·사후 비교를 확장할 수 있습니다. 스냅샷은 최근 7일만 보관하며 실현 수익률 비교나 정확도 통계는 제공하지 않습니다.
- 기사 분류는 Marketaux의 기업별 감성 점수, 사용자가 연결한 게이트웨이, 또는 두 AI 모델이 합의한 기사 분위기 판단에서 옵니다. 상단 요인 문장은 이 분류를 주제별로 세는 규칙 기반 종합입니다. MoneyCast가 자동 생성한 투자 전망, 개인화된 매매 지시 또는 확정 주가 예측이 아닙니다.
