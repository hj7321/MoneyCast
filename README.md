# MoneyCast

한국어 목표 자금 계산기와 뉴스 근거 확인 서비스입니다. 비어 있던 `D:\moneycast`에 npm workspaces로 구성했습니다. 웹과 iOS·Android 앱이 동일한 TypeScript 계산·검증·회사 식별·뉴스 계약을 사용합니다.

## 빠른 시작

Node.js **22.12 이상**(검증 환경 24.19), npm이 필요합니다.

```powershell
cd D:\moneycast
npm ci
npm run dev
```

- 웹: <http://127.0.0.1:5173>
- API: <http://127.0.0.1:8787/api/health>
- 뉴스 설정 없이 계산기를 사용할 수 있습니다. 뉴스에는 **데이터 연동 대기**가 표시됩니다.
- 종료: 실행 터미널에서 `Ctrl+C`. 5173·8787 포트가 다른 프로그램에 사용 중이면 먼저 확인하세요.

빌드된 웹과 API를 하나의 서버로 실행:

```powershell
npm run build
npm start
```

이때 웹 주소는 <http://127.0.0.1:8787>입니다. `npm start`는 현재 Node 환경에서 TypeScript 서버를 실행합니다. 공개 웹 주소는 <https://moneycast.vercel.app>입니다.

## 모바일

Expo SDK 54, React Native 0.81.5, React 19.1.0의 호환 조합을 사용합니다. 웹은 React/Vite이며 UI는 플랫폼별로 구현했습니다. 공유 계산 모듈에는 DOM·네이티브 종속성이 없습니다.

```powershell
npm run mobile
npm run mobile:android
# macOS + Xcode에서만 iOS 시뮬레이터 실행 가능
npm run mobile:ios
```

`mobile`로 Metro를 띄우고 SDK 54와 호환되는 Expo Go 또는 개발 빌드에서 실행하세요. 최신 Expo Go가 SDK 54를 지원하지 않을 경우 호환 Android Expo Go 또는 개발 빌드가 필요합니다. Android 에뮬레이터는 Android Studio/SDK 설정이 필요합니다. Windows에서는 iOS 네이티브 빌드를 할 수 없습니다.

뉴스 연결 시에만 모바일의 공개 서버 주소를 설정합니다.

```powershell
Copy-Item apps/mobile/.env.example apps/mobile/.env
```

`apps/mobile/.env`의 `EXPO_PUBLIC_API_URL`:

- Android 에뮬레이터: `http://10.0.2.2:8787`
- iOS 시뮬레이터: `http://127.0.0.1:8787`
- 실제 기기: 같은 네트워크 개발 PC의 LAN 주소, 예: `http://192.168.0.10:8787`
- 배포 환경: `https://moneycast.vercel.app`

실제 기기 연결은 신뢰하는 로컬 네트워크에서 API를 `HOST=0.0.0.0`으로 실행하고 해당 포트 접근을 허용해야 합니다. 기본값은 PC 내부 전용 `127.0.0.1`입니다. 설정 변경 후 Metro를 재시작하세요. 계산기는 서버 없이 작동합니다. **MARKETAUX_API_TOKEN과 NEWS_API_KEY를 EXPO_PUBLIC_* 또는 VITE_* 변수에 넣지 마세요.** 자세한 내용은 [모바일 안내](apps/mobile/README.md)를 참고하세요.

## 화면과 기능

- 목표 자금 계산기: 자유 목표/내 집/자동차/여행 예시, 직접 입력, 즉시 재계산, 원금·수익·목표 차이·달성 여부. 기본 화면은 계산기이며 이전 `#dashboard` 주소도 계산기로 연결됩니다.
- 소개 화면: `#calculator-intro`, `#news-intro`. 사이드바와 기능 화면의 **계산기 사용법·인사이트 사용법** 버튼에서 열고, 시작 버튼으로 실제 기능에 진입합니다.
- 웹 사이드바: 기본 열림이며 상단 메뉴 버튼으로 닫고 펼칩니다. 상태는 `sessionStorage`의 `moneycast.sidebar`에만 보관해 같은 브라우저 탭에서 새로고침할 때 유지됩니다. 새 세션은 열림으로 시작하고, 영구 저장·서버 동기화는 하지 않습니다. 저장소 접근이 차단되어도 토글은 작동합니다.
- 모바일 웹 하단 메뉴는 **목표 자금 계산기·뉴스 인사이트·이용 안내**입니다. 네이티브 앱의 두 기능 이름도 웹과 통일했습니다. 계산기의 중복 기능 탭은 제거했습니다.
- 웹의 사이드바·기능 화면과 네이티브 앱에서 **계산기 사용법·인사이트 사용법** 버튼을 제공합니다. 앱에서는 스크롤 가능한 안내 모달이 열리며 닫기 버튼과 Android 뒤로 가기를 지원합니다.
- 웹: 월별 SVG 차트, 목표선, 키보드 슬라이더, 연 수익률 ±2%p 시나리오, CSV 저장, 모바일 하단 내비게이션.
- 앱: 계산·뉴스 탭, 작은 화면용 선택 가능한 자산/원금 막대 차트, 목표선과 선택 시점 수치.
- 뉴스: 회사명·티커·시장으로 식별하는 정적 8개 회사 검색, 기사 출처·시각·분류 근거, 불확실성·요인·유의 문구.
- 뉴스 인사이트 상단의 긍정·부정 요인 박스는 여러 기사의 반복 주제·출처 수·최신 날짜·엇갈림을 규칙으로 종합하고, 문장마다 근거 기사로 이동하는 버튼을 둡니다. 기사별 점수 설명은 기사 카드의 **분류 근거**(최대 5줄)에, 기사 내용은 **핵심 요약**(최대 3줄)에 둡니다. 기사가 8건을 넘으면 나머지는 **더 보기**로 펼칩니다.
- Marketaux와 GDELT를 함께 조회하고 같은 기사는 하나로 합칩니다. 출처별 상태(정상·한도·실패)와 AI 판단 상태를 표시하며, 모든 출처가 실패하면 마지막 정상 결과를 **이전 결과** 배너와 함께 보여줍니다.
- 감성 점수가 없는 기사는 서버에 키가 있으면 Gemini와 Cloudflare Workers AI가 각각 판단하고, 두 판단이 같을 때만 **AI 합의**로 확정합니다. 한 모델만 답하면 **잠정**, 엇갈리면 **판단 유보**이며 둘 다 상단 집계에서 제외합니다.
- 뉴스 미설정·로딩·오류·호출 제한·기사 없음·근거 부족 상태. **가짜 기사나 정확도 수치는 제공하지 않습니다.**
- 계산 입력은 메모리에서 처리하며 서버로 보내지 않습니다. 새로고침하면 기본값으로 돌아갑니다. 로그인·결제·동기화는 포함하지 않습니다.

## 계산 규칙

연 수익률을 **실효 연 수익률**로 해석합니다.

```text
개월 수 = 목표 기간(년) × 12  (정수 개월)
월 수익률 = (1 + 연 수익률 / 100)^(1/12) - 1
이번 달 자산 = 지난달 자산 × (1 + 월 수익률) + 월 납입액
```

납입은 **매월 말**입니다. 예: 월 수익률 1%, 시드 100만 원, 월 10만 원이면 첫 달 자산은 111만 원입니다. 이자는 이전 잔액에만 붙습니다. 내부 계산에는 `log1p`/`expm1`을 사용하고 중간 반올림은 하지 않습니다. 월별 표시 자산과 원금만 원 단위로 반올림하며, 표시 수익은 둘의 차이여서 화면 수치가 일치합니다. 목표 차액은 `예상 자산 - 목표 금액`입니다.

- 금액: 0~1조 원, 수익률: -100% 초과~100% 이하, 기간: 1~600개월(50년). 웹·앱은 개월 수를 정수로 입력하며 기본값은 60개월(5년)입니다. 웹 슬라이더도 1개월 간격입니다. 계산 함수에는 입력한 개월 수를 12로 나눠 전달하고, 화면에는 13개월을 ‘1년 1개월’처럼 표시합니다.
- 누락·음수 금액·NaN·Infinity·월 단위가 아닌 기간·정밀도 범위 초과는 오류로 표시합니다. 음수 수익률은 손실 가정으로 지원합니다.
- 목표 0원은 목표 미설정입니다. 모든 납입액이 0원인 계산도 가능합니다.
- 기본값: 시드 1,000만 원, 월 50만 원, 연 5%, 5년, 목표 5,000만 원. 사용자 가정이며 시세나 추천 수익률이 아닙니다.
- 시나리오는 ±2%p를 적용한 비교이며 허용 수익률 범위로 제한합니다. 발생 확률이나 실제 시장 전망이 아닙니다.
- **세금·수수료·물가상승률·납입 변동·실제 시장 변동은 미반영**입니다. 실제 결과와 다를 수 있으며 수익을 보장하지 않습니다.

## 뉴스 연결과 환경변수

기본 구성은 **Marketaux 뉴스 API와 GDELT DOC 2.0을 함께 조회**합니다. Marketaux는 서버용 API 토큰이 있어야 요청하고, GDELT는 키가 필요 없습니다. 한쪽이 한도에 걸리거나 실패해도 다른 출처의 기사로 화면을 채우며, 기사마다 수집 출처를 표시해 다른 출처로 몰래 바꾸지 않습니다. 출처가 모두 실패하면 해당 상태와 마지막 정상 결과를 표시하며 예시 기사로 채우지 않습니다. 기존 사용자 소유 HTTPS 게이트웨이는 `NEWS_PROVIDER=gateway`로 계속 사용할 수 있으며, 이때는 게이트웨이만 단독으로 사용합니다.

> **이번 개편으로 바뀐 원칙** (2026-10-28)
> - 출처 하나만 쓰던 방식에서 **여러 출처를 함께 조회**하는 방식으로 바꿨습니다(`NEWS_SOURCES`).
> - 주기적으로 요청하지 않던 방식에서 **하루 한 번 예약 수집**(Vercel Cron, 06:00~06:59 KST)으로 바꿨습니다. 결과는 비공개 Vercel Blob에 회사별 스냅샷으로 보관합니다.
> - 원문을 그대로 표시하던 방식에 더해, AI 키를 설정하면 **AI가 제목과 매체 설명만 보고 쓴 한국어 요약**을 표시합니다. 기사 본문은 여전히 수집·저장·표시하지 않습니다.

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

이미 `.env`가 있다면 필요한 항목만 추가하세요. [Marketaux 무료 계정](https://www.marketaux.com/register)을 만든 뒤 대시보드의 토큰을 루트 `.env`에 저장합니다. 토큰을 채팅, 클라이언트 입력창, `VITE_*` 또는 `EXPO_PUBLIC_*` 변수에 넣지 마세요.

```dotenv
NEWS_PROVIDER=marketaux
MARKETAUX_API_TOKEN=발급받은_서버_전용_토큰
```

| 변수 | 위치 | 용도 |
| --- | --- | --- |
| `NEWS_PROVIDER` | 루트 `.env` | `marketaux`(기본, 아래 출처 조합 사용) 또는 `gateway` |
| `NEWS_SOURCES` | 루트 `.env` | 함께 조회할 출처. 기본 `marketaux,gdelt`, 하나만 적으면 다른 출처는 끔 |
| `MARKETAUX_API_TOKEN` | 루트 `.env` | Marketaux 서버 전용 API 토큰 |
| `NEWS_PROVIDER_URL` | 루트 `.env` | `gateway` 선택 시 신뢰하는 HTTPS 게이트웨이 URL |
| `NEWS_API_KEY` | 루트 `.env` | `gateway` 선택 시 서버 전용 Bearer 인증 키 |
| `CRON_SECRET` | Vercel 환경변수 | 예약 수집 경로 인증값(16자 이상 무작위 문자열). 없으면 수집 경로가 503 |
| `BLOB_READ_WRITE_TOKEN` | 루트 `.env`(로컬만) | 로컬에서 비공개 Blob 스냅샷을 쓸 때의 토큰. Vercel에서는 스토어를 프로젝트에 연결하면 `BLOB_STORE_ID`와 OIDC가 자동 설정 |
| `GEMINI_API_KEY` | 루트 `.env`·Vercel | Google AI Studio의 Gemini API 키(결제 계정 미연결) |
| `GEMINI_MODEL` | 루트 `.env`·Vercel | 기본 `gemini-3.5-flash-lite` |
| `CLOUDFLARE_ACCOUNT_ID` | 루트 `.env`·Vercel | Cloudflare 계정 ID(32자리 16진수) |
| `CLOUDFLARE_API_TOKEN` | 루트 `.env`·Vercel | Workers AI Read·Edit 권한의 API 토큰(Free 플랜) |
| `CLOUDFLARE_AI_MODEL` | 루트 `.env`·Vercel | 기본 `@cf/qwen/qwen3-30b-a3b-fp8` |
| `LLM_PROVIDERS` | 루트 `.env`·Vercel | 비우면 두 모델 모두 사용. `gemini`처럼 하나만 적으면 다른 모델을 끄며, 이때 AI 판단은 모두 잠정으로 남음 |
| `PORT` | 루트 `.env` | API 포트, 기본 8787 |
| `HOST` | 루트 `.env` | 바인딩 주소, 기본 127.0.0.1 |
| `EXPO_PUBLIC_API_URL` | `apps/mobile/.env` | 모바일에 공개되는 API 주소만 지정 |

모든 키는 서버 전용입니다. `VITE_*`·`EXPO_PUBLIC_*` 변수나 클라이언트 입력창에 넣지 마세요. AI 키가 하나도 없으면 AI 판단과 요약을 건너뛰고 출처의 분류만 표시합니다.

API 포트 변경 시 `apps/web/vite.config.ts`의 개발/미리보기 프록시도 바꾸세요. `.env`는 Git에서 제외됩니다. `npm run dev`는 `.env` 저장 시 API를 다시 시작해 설정을 읽습니다. `npm start`로 실행 중이면 직접 서버를 다시 시작하세요. 이미 실행 중인 개발 서버 위에 `npm run dev`를 중복 실행하면 포트 충돌이 발생합니다.

Marketaux에는 최근 7일의 기사 최대 3건을, GDELT에는 최근 7일의 영어 기계 번역 색인에서 기사 목록 최대 15건을 요청하며, 같은 회사 결과는 6시간 재사용합니다. GDELT 기사는 제목에 회사명이 있고 다른 회사·우선주를 가리키지 않을 때만 포함하며, 감성 점수가 없어 AI가 판단하기 전까지 미분류입니다. GDELT 시각은 처음 확인한 시각이라 카드에 **GDELT 확인** 시각으로 표시합니다. 한국 회사는 Entity Search에서 종목 코드·회사명·국가·거래소를 확인하고 제공자 티커를 찾습니다. 미국 회사도 기사에 연결된 기업의 티커·국가·이름을 검증합니다. 식별이 모호하면 다른 회사 기사를 대신 보여주지 않습니다. 제공자가 거래소를 생략한 경우에는 이 한계를 표시합니다. 기사 본문을 수집하지 않으며 제목·출처·게시 시각·원문 링크·언어·매체 설명(최대 300자 저장, 160자 표시)·해당 기업의 제공자 감성 점수를 표시합니다.

감성 점수는 -1~1이며 0보다 크면 긍정, 작으면 부정, 0이면 중립으로 표시합니다. 이는 뉴스 문맥의 감성 점수이며 상승 확률이 아닙니다. 점수가 없으면 미분류로 표시하고 근거 집계에서 제외합니다. 언어를 제한하지 않아 영어 등 해외 기사가 포함될 수 있으며, 한국 종목·한국어 기사 공급 범위와 실제 계정 이용 한도는 호출 결과 및 제공자 대시보드에서 확인해야 합니다.

[공식 무료 요금 안내](https://www.marketaux.com/pricing)는 2026-10-27 확인 기준 하루 100회·뉴스 요청당 3건입니다. 한국 종목 최초 식별 요청도 호출 수에 포함될 수 있습니다. 자동 페이지 추가는 하지 않으며, 주기적인 요청은 하루 한 번의 예약 수집뿐입니다(8개 회사 × 1회). HTTP 402/429는 호출 제한으로 처리하고 제공자가 알린 재시도 간격을 지킵니다. 정확한 계약·오류·캐시 정책과 게이트웨이 예시는 [서버 API 안내](server/README.md)에 있습니다.

서버를 켠 상태에서 `npm run news:check -- nasdaq:AAPL`로 실제 연동 상태를 확인할 수 있습니다. 미국 종목을 먼저 확인하고 `npm run news:check -- krx:005930`로 한국 종목의 공급 여부를 확인하세요. 출처별 상태, AI 모델별 상태와 합의·잠정·유보 건수도 출력합니다. 끝에 `--ai`를 붙이면(`npm run news:check -- nasdaq:AAPL --ai`) AI가 판단한 기사를 번호를 붙여 한 줄씩 보여 주고 두 모델의 일치율을 계산합니다. 모델 호출이나 응답 검증에 실패하면 API 서버 로그에 HTTP 상태·오류 코드·검증 실패 사유별 건수만 남기며, 응답 본문과 키는 남기지 않습니다. 서버 캐시가 없으면 뉴스와 AI 무료 한도를 사용합니다. 명령 자체는 키를 출력하지 않습니다. 키 설정 전에는 `not_configured`와 기사 0건이 정상이며 실제 연결 성공을 뜻하지 않습니다.

### AI 교차 판단과 요약

감성 점수가 없는 기사(GDELT 기사, 점수 없는 Marketaux 기사)는 두 무료 LLM이 **서로의 답을 보지 않고 병렬로** 판단합니다. 최종 결과는 어느 한 모델이 아니라 아래 규칙으로 정합니다. Marketaux 점수가 있는 기사의 방향은 AI가 바꾸지 않습니다.

| 두 모델의 답 | 결과 | 상단 요인 집계 |
| --- | --- | --- |
| 같은 방향(긍정·부정·중립) | **AI 합의**(확정) | 포함 |
| 방향이 다름, 한쪽이라도 '판단 불가', 관련성 판단이 다름 | **판단 유보** | 제외 |
| 한 모델만 답함(한도·장애·시간 초과·검증 실패) | **잠정**. 다음 갱신 때 빠진 모델만 다시 확인 | 제외 |
| 두 모델 모두 답하지 않음 | **미분류**. 다음 갱신 때 재시도 | 제외 |
| 두 모델 모두 '관련 없음' | 목록에서 숨기고 건수만 표시 | 제외 |

- **Gemini**(기본 `gemini-3.5-flash-lite`)가 방향·근거 구절·이유·주제와 **한국어 요약 1~2문장**을 맡고, **Cloudflare Workers AI**(기본 `@cf/qwen/qwen3-30b-a3b-fp8`)는 요약 없이 방향·근거·이유만 독립적으로 답합니다. Gemini를 호출할 수 없는 동안에는 Cloudflare가 요약을 대신 씁니다.
- 모델에는 회사명·별칭·종목 코드와 기사별 제목·매체 설명·매체·언어만 보냅니다. 본문·URL·기사 ID는 보내지 않습니다. 기사 텍스트 안의 지시는 따르지 않도록 하고, 도구는 주지 않습니다.
- 서버가 모든 답을 검증합니다: 응답 형식과 ID, 근거 구절이 제목·설명에 실제로 있는지, 입력에 없는 숫자, 투자 권유·확률·주가 전망 표현(기사가 직접 보도한 증권사 의견은 허용), 길이. 통과하지 못한 답은 그 모델의 무응답으로 처리합니다.
- 판단과 요약은 스냅샷의 7일 기사 목록에 함께 저장해 같은 기사를 다시 판단하지 않습니다. 호출 1회당 기사는 최대 15건입니다.
- 요청 시 갱신은 모델 호출을 포함해 18초 안에 끝내고(클라이언트 제한 20초), 남은 시간이 6초 미만이면 모델을 부르지 않습니다. 예약 수집은 회사당 최대 60초까지 기다립니다. 모델 장애·한도·시간 초과는 뉴스 응답을 막지 않습니다.
- 한도: Gemini 429는 Google이 알린 대기 시간(1분~1시간), Cloudflare의 하루 무료량 소진(오류 코드 3036)은 다음 00:00 UTC까지 해당 모델 호출을 쉽니다.
- 화면에는 카드 배지(AI 합의·잠정·판단 유보), 분류 근거(모델별 판단·근거 구절·이유), 요약 기준(제목·설명 또는 제목만), 모델별 상태 줄, "일부 요약·분류는 AI가 생성했으며 틀릴 수 있습니다" 안내를 표시합니다.

분류된 최근 기사 3건 미만, 오래된 기사, 모두 중립, 긍정·부정 상충이면 판단을 유보합니다. 분류된 기사는 제공자 점수가 있는 기사와 두 AI가 합의한 기사뿐이며, 미분류·잠정·판단 유보 기사는 3건 기준에서 제외합니다. 근거 수준은 기사 수·최신성·상충에 따른 표시 규칙이며 예측 정확도가 아닙니다. 다음 주는 **서울 기준 다음 달력 주의 월~금**이며 거래소 휴장일과 시장별 거래 시간은 미반영입니다. 뉴스가 미래 주가 방향이나 원인을 증명하지 않는다는 유의 문구를 화면에 표시합니다.

## 뉴스 캐시와 배포

정상 뉴스는 회사별 **6시간** 캐시합니다. 다음 주 참고용 뉴스이므로 12~24시간의 큰 지연을 피하면서, 8개 회사 기준 하루 최대 네 번의 정상 갱신으로 무료 API 호출을 줄이는 절충안입니다. 조회 시점은 화면에 표시합니다. 캐시를 읽거나 메뉴를 이동해도 원래 만료 시각은 늘어나지 않습니다.

- 웹은 메모리와 localStorage를 함께 사용해 메뉴 재진입·새로고침 시 같은 분석을 재사용합니다. 저장소가 차단되면 메모리만 사용합니다.
- 앱은 프로세스 메모리 캐시와 서버 결과를 재사용합니다. 앱을 완전히 종료하면 앱 메모리는 초기화됩니다.
- 서버는 성공·근거 부족 결과를 6시간, 일부 출처가 실패한 부분 결과를 30분, 오류·미설정 상태를 5초 캐시합니다. 호출 제한은 최소 1분 또는 제공자가 지정한 시각까지 기다립니다.
- 모든 출처가 실패하면 서버 메모리나 스냅샷의 마지막 정상 결과(7일 이내)를 `servedFrom: "stale"`로 표시해 반환합니다. 웹·앱도 마지막 정상 결과를 따로 보관했다가 API에 연결할 수 없을 때 **이전 결과** 배너와 함께 보여줍니다. 이전 결과는 CDN에 캐시하지 않습니다.
- Vercel CDN에는 정상 뉴스만 원래 만료 시각까지 캐시하며, 오류·호출 제한 응답은 저장하지 않습니다.

**예약 수집과 스냅샷.** Vercel Cron이 매일 `0 21 * * *`(UTC, 06:00~06:59 KST)에 `/api/cron/collect`를 `Authorization: Bearer <CRON_SECRET>`로 호출합니다. 8개 회사를 차례로 새로 고쳐 회사별 스냅샷 `news/news-evidence-v3/<회사>.json`을 비공개 Blob에 저장하고, 결과 요약(`refreshed`·`failed`·`skipped`)만 반환합니다. Hobby 플랜 Cron은 하루 1회·최대 59분 지연·재시도 없음이며 중복 실행될 수 있어, 수집은 몇 번 실행해도 결과가 같도록 회사 스냅샷만 덮어씁니다. 요청은 메모리 → 스냅샷 → 실시간 순으로 읽고, 스냅샷이 아직 유효하면 외부 API를 호출하지 않습니다. 스냅샷에는 최근 분석과 7일 기사 목록(최대 30건, AI 판단·요약 포함)이 들어가며, 내용이 같으면 6시간에 한 번만 다시 씁니다. Blob을 읽거나 쓰지 못해도 응답은 실시간 조회로 계속됩니다. 함수 최대 실행 시간은 300초이며, 수집은 시작 후 200초가 지나면 남은 회사를 요청 시 갱신에 맡깁니다.

Vercel 프로젝트는 GitHub `hj7321/MoneyCast` 저장소와 연결되어 있습니다. 프로덕션 브랜치는 `main`이며, `main`에 푸시하면 자동으로 빌드·배포하고 성공한 결과를 <https://moneycast.vercel.app>에 반영합니다. 빌드가 실패하면 기존 정상 배포가 유지되며 Vercel 배포 로그에서 원인을 확인할 수 있습니다. 다른 브랜치는 Preview 배포로 확인할 수 있습니다. 뉴스 API 키는 Vercel의 서버 환경변수에서 관리하며 GitHub 저장소에 추가하지 않습니다. CLI 수동 배포도 사용할 수 있고 기존 GitHub LICENSE와 이력은 유지합니다.

웹·앱 글꼴은 **IBM Plex Sans KR**이며 기존 크기·굵기 값을 유지합니다. 뉴스 안내 버튼은 **인사이트 사용법**입니다. 회사 파비콘은 로컬 파일로 포함하고, 원본·해시·글꼴 라이선스는 [자산 안내](assets/README.md)에 기록합니다.

## 검증

```powershell
npm run typecheck     # 공용 코어·서버·웹·모바일 TypeScript
npm test              # 계산, UI, API·제공자·정적 파일 테스트
npm run build         # 웹 프로덕션 빌드
npm run mobile:export # iOS·Android Hermes JavaScript 번들
```

자동 테스트는 외부 뉴스·LLM API를 모의 응답으로 대체하며 실제 계정의 쿼터를 사용하지 않습니다. 코어는 계산 경계값·복리·반올림·검색과 감성 점수·미분류·출처 메타데이터 검증을 확인합니다. 서버는 회사 혼동·잘못된 응답·401/403·402/429·시간 초과·근거 부족·상충·캐시·정적 파일 경계를 확인합니다. 웹 UI는 폼·차트·메뉴·세션 복원과 뉴스 언어·분류·수집 기간·캐시 시각·재시도 제한을 확인합니다.

뉴스 인사이트 개편(2026-10-28) 후 **자동 테스트 162개(코어 31·웹 UI 및 캐시 45·서버 86)**가 모두 통과했습니다. 서버 테스트는 주제별 종합 문장, 출처 결합·중복 제거·회사 혼동, GDELT 요청 간격·응답 검증, 스냅샷·예약 수집 인증과 멱등성, AI 합의 규칙의 모든 경우·검증기(근거 구절·숫자·권유 표현)·두 어댑터의 요청 형식과 한도 처리·시간 예산을 확인합니다. 이전 기준은 Marketaux 연동과 월 단위 입력 보완 후 112개(코어 27·웹 UI 및 캐시 39·서버 46)였습니다. 개별 결과는 실행 시 출력이 기준입니다. 월 단위 입력은 1·12·13·600개월의 원금과 차트, 1개월 간격 슬라이더, 누락·0·음수·소수·범위 초과 오류 및 복구를 검증합니다. 전체 TypeScript 검사, 웹 프로덕션 빌드와 최신 iOS·Android Hermes 번들 생성도 확인했습니다.

실제 뉴스 연결은 2026-10-27 한국 시간 22:31~22:33에 별도 확인했습니다. `news:check`로 애플(AAPL)과 삼성전자(005930)에서 각각 실제 기사 3건과 해당 기업의 감성 분류 3건을 수신했습니다. 당시 두 회사 모두 긍정·부정 분류가 상충해 `insufficient`/판단 유보를 반환했으며 연결 실패가 아닙니다. 브라우저에서도 원문 링크·언어·감성 분류·게시 시각·기업 식별·수집 기간·캐시 정보를 확인했고, 노트북 및 모바일 너비에서 가로 넘침이 없었습니다. 실제 기사 수와 분류는 조회 시점에 따라 바뀝니다. API 토큰이 웹·앱 빌드나 개발 서버 로그에 포함되지 않은 것도 점검했습니다.

2026-10-28 한국 시간 04:04~04:05에는 공개 Vercel 주소의 상태 API·회사 검색·폰트·파비콘을 확인했습니다. 애플과 삼성전자에서 각각 실제 기사 3건을 수신했고, 동일 URL 재조회는 `X-Vercel-Cache: HIT`와 같은 기준 시각·만료 시각을 반환했습니다. 배포 브라우저에서 1개월 입력의 즉시 재계산, 회사 파비콘 8개 로딩, IBM Plex Sans KR 지정, 요청한 검정·회색 텍스트와 가로 넘침 없는 화면도 확인했습니다.

이전에 작은 화면과 노트북 너비의 레이아웃·입력·검색·연동 대기를 브라우저에서 확인했으며, 초기 구현에서 iOS·Android Hermes 번들 생성을 확인했습니다. 모바일 번들은 실기기 실행이나 네이티브 앱 패키징을 대신하지 않습니다. iOS/Android 실기기, 앱 서명과 스토어 배포는 검증하지 않았습니다.
